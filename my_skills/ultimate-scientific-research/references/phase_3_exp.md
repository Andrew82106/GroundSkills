# 阶段 3：实验设计 — 详细执行规范

## 触发条件

当 `project_state.json` 中 `current_phase == 3` 时加载本文件。

## 前置检查

进入本阶段前，检查 `02_lit/related_work.md` 是否存在且包含三大硬指标（SOTA、Gap、Positioning）。如果不完整，拒绝进入。

## 执行流程

### 步骤 1：从文献综述中提取设计约束

阅读 `02_lit/related_work.md`，从中推导出实验设计的硬性约束：

- **SOTA 基线**：综述中锚定的 2-3 个 SOTA 方法，它们就是我们必须对比的 Baseline
- **标准 Benchmark**：SOTA 方法在哪些数据集上报告了性能？我们的实验也必须覆盖这些数据集
- **评估指标**：SOTA 方法使用了哪些 Metrics？我们必须采用相同指标以确保公平对比
- **Gap 驱动的新实验**：综述中识别的 Gap 本身也需要设计实验来验证——比如新增一个 ablation study 来证明我们确实填补了这个缺口

### 步骤 2：结构化实验设计矩阵

强制输出以下矩阵格式：

```json
{
  "experiment_design": {
    "research_question": "一句话重述核心研究问题",
    "hypothesis": "我们期望验证的核心假设",
    
    "datasets": [
      {
        "name": "数据集名称",
        "source": "来源 URL 或引用",
        "size": "样本数 / 规模",
        "split": "train/val/test 划分方式",
        "why": "为什么选这个数据集（必须回答）"
      }
    ],
    
    "baselines": [
      {
        "name": "基线方法名",
        "paper": "来源论文",
        "implementation": "官方代码 / 复现代码 URL",
        "why": "为什么选它作为对比（必须回答）"
      }
    ],
    
    "metrics": [
      {
        "name": "指标名称（如 F1, BLEU, Accuracy）",
        "formula": "简述计算方式",
        "why": "为什么用这个指标"
      }
    ],
    
    "ablation_studies": [
      {
        "name": "消融实验名称",
        "removes": "移除了什么组件",
        "purpose": "验证什么假设"
      }
    ],
    
    "resource_estimate": {
      "gpu_type": "推荐 GPU 型号",
      "gpu_hours": "预估总 GPU 小时数",
      "storage_gb": "预估存储需求",
      "feasibility_note": "对当前用户资源条件的可行性评估"
    }
  }
}
```

每个条目中的 `why` 字段是强制的——这是防止"假大空实验设计"的关键约束。如果你无法给出令人信服的 `why`，说明这个选择可能是错误的。

### 步骤 3：算法伪代码

除了矩阵之外，还需要输出核心算法的高质量伪代码：

- 使用清晰的伪代码语法（非某个具体编程语言）
- 标注关键步骤的时间复杂度
- 标注与 SOTA 方法的差异点（用注释标记"本文创新点"）

### 步骤 4：生成初始化脚本

生成 `setup.sh`，用于一键搭建实验环境：

```bash

# Auto-generated by Ultimate Scientific Research Orchestrator

set -e

echo "=== Setting up experiment environment ==="

# 创建 Python 虚拟环境
python3 -m venv .venv
source .venv/bin/activate

# 安装依赖（根据实验设计自动生成）
pip install -r requirements.txt

# 下载数据集（如果有公开下载链接）
echo "=== Downloading datasets ==="
# [根据 datasets 配置自动生成下载命令]

echo "=== Setup complete ==="
```

### 步骤 5：生成 Checkpoint

将上述产物写入 `03_planning/`：

- `03_planning/experiment_design.json` — 完整的实验设计矩阵
- `03_planning/algorithm.md` — 核心算法伪代码
- `03_planning/setup.sh` — 环境初始化脚本

展示给用户，**停机等待用户批准**。

## Gotchas

- 不要设计你明知道跑不动的实验。如果用户只有一块 3090，就不要建议在 8xA100 上跑 70B 模型。在 `resource_estimate` 中诚实评估。
- 不要遗漏 ablation study。审稿人最常问的问题就是"你的每个组件真的都有用吗？"消融实验是对此的直接回答。
- `why` 字段如果你写不出有说服力的内容，说明你需要回到阶段 2 重新确认那个选择是否合理。
