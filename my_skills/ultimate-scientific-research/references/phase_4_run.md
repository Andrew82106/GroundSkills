# 阶段 4：执行与图表化 — 详细执行规范

## 触发条件

当 `project_state.json` 中 `current_phase == 4` 时加载本文件。

## 前置检查（物证拦截）

进入本阶段前，执行以下强制检查：

1. `03_planning/experiment_design.json` 存在且非空
2. `03_planning/setup.sh` 存在
3. 上述文件的内容经用户在前一阶段批准过（通过 `project_state.json` 中的 `decisions` 数组确认）

**如果任何条件不满足，立即拒绝执行。** 向用户解释："实验设计尚未经审批，贸然写代码会导致大量返工。请先完成阶段 3。"

## 执行流程

### 步骤 1：部署模式确认

生成代码之前，**必须先主动询问用户**：

> 当前实验是在本机直接运行，还是需要推送到远端算力集群？
> 1. **本地执行** — 我会生成可以直接在当前终端运行的脚本
> 2. **远端部署 (SSH)** — 我会额外生成 SSH 连接脚本和远程执行 wrapper
> 3. **集群调度 (Slurm)** — 我会生成 `.sbatch` 作业提交脚本

根据用户选择调整后续代码生成策略。

### 步骤 2：代码实现

基于 `experiment_design.json` 中的矩阵，逐项实现：

**代码组织规范**：
```
04_experiments/
├── src/
│   ├── model.py          # 核心模型实现
│   ├── train.py          # 训练循环
│   ├── evaluate.py       # 评估脚本
│   ├── data_loader.py    # 数据加载与预处理
│   └── utils.py          # 通用工具函数
├── data/
│   └── README.md         # 数据来源说明与下载指引
├── configs/
│   └── default.yaml      # 超参数配置文件
├── run.sh                # 一键启动脚本（本地 or 远端）
└── requirements.txt      # Python 依赖列表
```

**代码质量底线**：
- 每个核心函数必须有 docstring
- 训练脚本必须包含 checkpoint 保存/恢复机制
- 评估脚本必须输出结构化的 JSON 结果（而非仅打印到 stdout）
- 所有超参数必须可通过配置文件或命令行参数修改（不得硬编码在代码中）

### 步骤 3：调试循环

代码编写完成后，运行测试：

1. 先跑一个 **微型验证 (Sanity Check)**：用极小的数据子集（如 100 条样本）跑 1-2 个 epoch，确认训练循环无 bug、loss 在下降
2. 如果 Sanity Check 报错，进入 **自主调试循环**：
   - 阅读错误日志
   - 定位根因（不是打补丁！）
   - 修复后重跑
   - 循环直到 Sanity Check 通过
3. Sanity Check 通过后，告诉用户可以开始完整训练

### 步骤 4：完整实验运行

根据用户确认的部署模式，执行完整实验：

- **本地**：直接运行 `run.sh`
- **远端**：通过生成的 SSH wrapper 或 Slurm 脚本提交作业

运行过程中，定期汇报进度（如"已完成 3/5 个实验配置"）。

### 步骤 5：结果收集与图表生成

实验结束后：

1. **收集结构化结果**：将所有实验的性能数字整合为一个 `results_summary.json`
2. **调用可视化子 Skill**：通过动态扫描结果中标记为"科学可视化"能力的子 Skill，生成出版级图表。如果没有对应子 Skill，自行使用 matplotlib 绘制。

**图表必须满足**：
- 分辨率 ≥ 300 DPI
- 字体大小适合论文栏宽（单栏 8pt+，双栏 6pt+）
- 包含完整的轴标签、图例和标题
- 配色应避免纯红/纯绿（色盲友好）

**典型图表需求**：
- 主结果对比表/图（我们 vs 所有 Baseline）
- Ablation study 结果图
- 关键超参数的敏感性分析图（如果 `experiment_design.json` 中包含）

### 步骤 6：生成 Checkpoint

将结果写入 `05_results/`：

- `05_results/results_summary.json` — 完整的实验结果数据
- `05_results/figures/` — 所有出版级图表（`.pdf` 和 `.png` 双格式）
- `05_results/analysis.md` — 结果分析摘要（包含关键发现和意外观察）

展示给用户，**停机等待用户验收数据和图表**。

## Gotchas

- **先 Sanity Check，再全量跑。** 千万不要一上来就启动完整训练。一个小 bug 浪费 48 小时 GPU 时间是不可接受的。
- **结果必须可复现。** 确保随机种子被固定，并记录在配置文件中。
- **不要美化结果。** 如果实验结果不如预期，如实报告。用户需要看到真实数据来做决策。
- **远端执行时的日志问题。** 如果使用 SSH/Slurm，确保生成的脚本中包含日志重定向，方便事后排查问题。
