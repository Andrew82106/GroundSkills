# 阶段 1：寻找 Idea 与概念推敲 — 详细执行规范

## 触发条件

当 `project_state.json` 中 `current_phase == 1` 时加载本文件。

## 核心原则

> **Agent 是辩手，用户是裁判。**
>
> 六顶思考帽辩论由 Agent 自行完成全部角色的输出与交锋。用户不参与辩论本身，只在辩论结束后对结论进行裁决（同意 / 否决 / 补充约束）。

## 执行流程

### 步骤 1：判断用户的起始状态

用户进入阶段 1 有两种可能：

**情况 A — 用户带着一个原始想法 (Raw Idea)**：
进入"六顶思考帽自辩论"流程（见步骤 2）。

**情况 B — 用户没有想法，只给了一个大方向**（如"我想在 NLP 安全领域做点东西"）：
通过调用文献检索子 Skill，在该领域顶刊顶会中检索最近 12 个月的论文，识别 3 个未被充分探索的研究缝隙 (Gap)，以结构化方式呈现给用户选择。用户选定后，进入步骤 2。

### 步骤 2：六顶思考帽自辩论 (Six Thinking Hats Self-Debate)

当用户给出 Raw Idea 时，你**绝不允许**直接附和。但你也**绝不允许**把拷问直接抛给用户。你必须自行扮演六顶帽的全部角色，独立完成辩论。

#### 辩论机制

辩论分为 **3-5 轮 (Rounds)**，每轮包含六顶帽的完整发言。Agent 在内部依次切换角色身份，进行真正的智力碰撞：

**Round 1 — 各帽独立立场输出**：
每顶帽根据用户的 Raw Idea，独立输出 1-2 段立场分析。此时各帽**不互相回应**，只专注于自己视角的判断。

**Round 2 — 交叉反驳**：
每顶帽阅读 Round 1 中其他帽子的输出，对与自己立场冲突的观点进行**有理有据的反驳或修正**。例如：
- 黄帽可能反驳黑帽的风险判断："该风险可通过 X 方法缓解"
- 黑帽可能反驳绿帽的替代方案："替代方案 B 存在 Y 问题"
- 白帽可能用新检索到的事实同时更新多方的假设

**Round 3 — 深度聚焦**：
针对前两轮中暴露出的**最核心分歧点**（通常 1-2 个），相关帽子进行定向深挖。其他帽子可保持沉默。

**Round 4-5（可选，仅在未收敛时触发）**：
如果 Round 3 后仍存在关键分歧未消解，继续聚焦辩论。如果已收敛，直接进入蓝帽裁决。

**蓝帽终局裁决**：
在所有辩论轮次结束后，蓝帽作为最终裁决者：
- 列出经过辩论后**依然站得住脚的核心论点**
- 列出**被击穿的论点**和建议调整的方向
- 输出一个经过锤炼的、逻辑闭环的**最终研究目标陈述**
- 标注**需要用户决策的开放点**（如应用领域选择、资源约束等 Agent 无法替用户决定的事项）

#### 六顶帽角色定义与职责

**⚪️ 白帽 (White Hat — 客观事实)**：
聚焦于可验证的客观信息。通过文献检索查证：
- 实现该 Idea 所需的数据集是否存在？质量和规模如何？
- 已发表的实验数据能否支撑核心前提假设？
- 算力需求处于什么级别？当前主流可用的资源能否覆盖？

**⚫️ 黑帽 (Black Hat — 风险与批判)**：
专职寻找致命缺陷，扮演最严苛的审稿人：
- 过往是否有人尝试过类似路线但失败？失败根因是什么？
- 此 Idea 是否存在理论层面的硬伤（假设过强、因果不清等）？
- 最坏情况下，做出来的结果是否可能只是 marginal improvement？

**🟡 黄帽 (Yellow Hat — 价值探寻)**：
专职论证最高价值：
- 此 Idea 解决的问题是否有真实的学术或工程需求？
- 如果成功，能在顶会中占据什么级别的位置？
- 与现有 SOTA 相比，独特竞争优势是什么？

**🟢 绿帽 (Green Hat — 创意替代)**：
跳出惯性思维，寻找不同路径：
- 是否有完全不同的技术路径可以达到同样的目标？
- 是否可以借鉴其他领域（跨领域迁移）的方法？
- 当前方案是否在"用复杂方法解决简单问题"？

**🔴 红帽 (Red Hat — 直觉与趋势)**：
基于学术嗅觉做判断：
- 此方向是否契合当下学术前沿的热点趋势？
- 审稿人看到题目，第一反应是"有意思"还是"又来了"？
- 做完后会不会让人兴奋？

**🔵 蓝帽 (Blue Hat — 统筹归纳)**：
不参与辩论本身，负责每轮的流程控制和最终裁决（见上方"蓝帽终局裁决"）。

### 步骤 3：呈递辩论报告

辩论完成后，将结果以以下结构呈递给用户：

```
## 📋 辩论报告

### 核心结论
[一段话总结经锤炼后的研究方向]

### 关键论点（站得住的）
1. [论点 + 支撑它的帽子和理由]
2. ...

### 被击穿的论点
1. [论点 + 击穿它的帽子和理由]
2. ...

### 建议调整
[基于辩论结果，对原始 Idea 的具体修正建议]

### ⚠️ 需要您决策的开放点
1. [Agent 无法替用户决定的事项，如领域选择、资源限制等]
2. ...
```

**关键**：用户只需要对"核心结论"和"开放点"做轻量反馈（同意 / 否决 / 补充），不需要回答六顶帽的具体问题。

### 步骤 4：用户反馈与迭代

用户反馈后的处理：

- **用户同意**：直接进入步骤 5（文献实证）。
- **用户否决或给出新约束**：Agent 将用户反馈作为新的输入条件，**仅对受影响的维度**重新展开定向自辩论（不需要完整的 6 帽全量重跑），然后再次呈递修订后的报告。
- **迭代上限**：用户-Agent 反馈迭代**最多 3 轮**。3 轮后必须收敛出一个双方都能接受的研究方向，否则蓝帽强制做出最终决策并明确标注分歧点。

### 步骤 5：文献实证

在研究方向确定后，必须使用文献检索子 Skill（或自行检索）获取实证支撑：

**检索硬约束**：
- 来源必须是该领域公认的顶级会议和顶级期刊（例如 NLP 领域：ACL、EMNLP、NAACL、TACL 等；CV 领域：CVPR、ICCV、ECCV、TPAMI 等）
- 严禁引用预印本作为唯一证据（可作为补充但不可作为主论据）
- 每个核心论点至少需要 2 篇独立论文交叉佐证
- **总文献数量不少于 8 篇**，覆盖研究方向的不同子维度（方法论、应用场景、理论基础等）

生成完毕后，按照 SKILL.md 中"上下文熔断与接力"的规范执行：
1. 更新 `project_state.json`
2. 生成恢复 Prompt（包含项目绝对路径 + 上阶段一句话结论，用户可直接复制到新对话）
3. **停机**，将 `ideation_log.md` 和恢复 Prompt 一并展示给用户，等待用户的明确批准后才能进入阶段 2。
